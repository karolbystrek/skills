# Agent guide

Central store of third-party skills and hooks, installed per project for Claude Code and Codex.

## Layout

- `sources.txt`: one upstream per line: `name repo folders... [hooks=<upstream hooks json>]`.
- `vendor/<name>/`: generated by `update.sh`. An unmodified upstream copy: `skills/<skill>/` (category folders flattened), `hooks/` (`*.js` + `hooks.json`), `LICENSE`, `UPSTREAM` (repo + commit). Never edit by hand; changes are lost on the next update.
- `update.sh`: re-fetches every upstream into `vendor/`.
- `install.sh <project> <package | package:skill>...`: installs into a project.

## What install.sh writes in a project

- Skills → `.agents/skills/<skill>/` (Codex); `.claude/skills` is a symlink to `../.agents/skills` (Claude Code).
- Hook scripts → `.agents/hooks/`. They must sit next to `.agents/skills`: ponytail's scripts read `../skills/ponytail/SKILL.md`.
- Hook config is merged into `.claude/settings.json` and `.codex/hooks.json`. Existing settings are kept and re-runs do not duplicate entries. Upstream commands point at the plugin cache (`$CLAUDE_PLUGIN_ROOT`); install rewrites them to the project copy.
- The Codex command sets `PLUGIN_DATA`, which ponytail's scripts use to detect Codex.

## Rules

- Adapt upstream files in `install.sh`, not in `vendor/`.
- `mattpocock` and `emilkowalski` both ship `prototype`. On a name clash, install keeps the skill from the package named first and logs the skipped one.
- The hook merge assumes every upstream command names a `hooks/<file>.js`. Check that before adding another package with hooks.
- After changing `install.sh`, install twice into a scratch git repo with an existing `.claude/settings.json`. Check that existing settings survive, hooks are not duplicated, and the installed SessionStart commands print ponytail's context.
- Skills are instructions agents run with shell access: review upstream diffs before committing an update.
